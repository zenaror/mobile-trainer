# RAM pointer operands (ramop6): independent verification of the first version (1,431 operands)

> Status: **reference (current)** for the corrections it lists.  The corrected pass: [`naming2_ramop6.md`](naming2_ramop6.md); mapping record: [`analysis/naming2/ramop6_names.tsv`](../../analysis/naming2/ramop6_names.tsv).

Verification of the first version of the mechanical pass (1,431 operands in 96 files, 210 mapping rows) on 2026-10-05 by a reader with a fresh context that had not seen the reasoning behind the rule.  Rules it was given: attack every row from the code (what does
the register do after the load, what do the callees do with it), hunt for constants and mismatches, judge the 28 operands the tool left numeric, run the tool and its tests, and judge every claim of the docstring and of `STYLE.md`; the repository stays
read-only (builds only in a private copy).  The reader could not write its report as a file (the harness asks subagents to return findings as text), so the text of its final reply is reproduced below, lightly reformatted.

## 1. Result

**UPHELD 192 rows / 1,387 operands, CORRECTED 2 rows / 4 operands, DROPPED 16 rows / 40 operands** of 210 rows / 1,431 operands (46 operands change: 45 go back to numeric, 1 is re-expressed).  The premise of the first version, "an immediate in HRAM is never a count",
was false for 30 operands.  Integration (what was done with it; the corrected pass is in `naming2_ramop6.md`): the tool got the rules the reader proposed (the first straight-line use of the register decides in HRAM and the hardware registers, a DE for
`Sprite_SetPosition` and a BC for `CommTime_DrawNumber` are values, an alias base is skipped only inside the files of its alias, a `; raw` comment keeps a number with its reason) and two tests per rule (14 in all); the tree was restored and the tool run
