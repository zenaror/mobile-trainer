### Keyboard indirect path

Decoding all 256 byte indices for the six local `JP HL` dispatches, including the `(index*2) & $FF` wrap, found one new conditional path into the interior of the keyboard fragment. `Kbd_LoadPageGraphics_T78` (`engine/keyboard/keyboard.asm:1918`, physical `55:696B–697B`) uses table base `$697C`; indices `$51` and `$D1` both wrap to offset `$A2`, read the word at `55:6A1E` (`00 5E`), and jump to `55:5E00`. The bytes there (`29 5F`) are the little-endian operand bytes of the normal `JP` at `55:5DFF`; decoded at the alternate entry they execute `ADD HL,HL` and `LD E,A`, then fall through to Select at `55:5E02`. This path does not enter the fragment's first byte at `55:5DF5`.

The explicit page producers examined are `Kbd_Open` (`55:5BB8`), which writes zero to `wKbdPage`, and Select (`55:5E27–5E31`), which increments the byte and resets it only when the result equals `$04`. Boot also clears `C000–DFFF` (`home/init.asm:60–64`). Under the zero-initialized normal path and absent other writers, these producers preserve values `0..3`; they do not generate `$51/$D1`. Nineteen textual `farcall Kbd_Open` sites and the two local calls to `Kbd_LoadPageGraphics` (`keyboard.asm:103,330`) reveal no additional explicit producer. Thus the alternate dispatch is **CONFIRMED conditional**, but natural entry/execution remains **HYPOTHESIS**; the invariant is conditional on initialization and the enumerated writers, not universal against arbitrary memory writes.
