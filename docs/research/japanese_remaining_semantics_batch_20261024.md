One conditional exception matters for bank42 tail `42:6132–6140`. `Account_ResultPage_LoadBanner` computes the first table record as `$7831 + 3*kind` and passes its source/bank to `Gfx_StartHDMAWithService`. If `wResultPage_Kind=$B5`, the index wraps to `$1F`, selecting bytes at `68:7850` (`06 5F 42`) inside the following `farcall CommTime_AddTimerA` instruction stream. Those bytes are interpreted as HL=`$5F06`, A=`$42`; the uploader aligns the source to `$5F00` and requests `$280` bytes, so the conditional DMA window `42:5F00–6180` overlaps `42:6132–6140`. With variant 0, a separate invalid-kind set `{0C,30,33,35,93,96,98}` reaches the same bytes through the second-banner index/list calculation.

The implemented explicit callers pass only kinds 0–4 (registration 0/4, password change 1, usage-time 2, usage-fee 3); `Account_ResultPage` is the sole named writer and `Account_ResultPage_LoadBanner` has one explicit named caller. Thus the invalid-state transfer is a **CONFIRMED conditional arithmetic/data path**, but a **HYPOTHESIS** as a natural execution or intended consumer: no producer or trace for those invalid kinds is established. It proves neither intended graphics use nor global unreachability. Do not create/rephase an asset or promote a semantic name from this path alone.
